# 제품 범위 변경 — 구매·수리 경로 확장

변경일: 2026-09-20. 사용자가 전달한 변경안을 기준으로 정리한 현재 요구사항이다. 요구사항 기준 문서다. 아래 현재 구현 상태는 같은 날 웹 앱 작업 후 갱신했다.

## 서비스 정의

> 사진으로 내 물건에 필요한 부품을 찾고, 정품부터 대체품까지 구할 수 있는 경로와 확인 근거를 안내합니다.

정품 부품 우선 조회에서 동일 제품 확인, 정품·타사·범용·중고 부품, 수리·제조사 문의까지 해결 경로를 확장한다. 이전 설계의 정품 구매 안내만 허용하는 범위는 이 변경안으로 대체한다. 타사 대체품도 출처와 적용 조건을 표시해 안내할 수 있다.

품목 범위는 생활 전반이다. 자전거·전자제품·가구·학용품은 예시이며 주방·위생·공구·원예·반려동물·육아·재봉·운동용품까지 확장했다. 실제 카탈로그의 13개 분야와 미등록 부품의 검색·문의 지원을 구분한다. [분야별 현재 범위](daily-life-expansion.md).

## 결과 화면

| 경로 | 표시할 내용 | 표시 조건 |
|---|---|---|
| 동일 제품 확인 | 제품 페이지·설명서, 모델·용량·세대 | 식별이 모호하면 동일 제품 확정 대신 제품 후보로 표시 |
| 정품 부품 | 공식 구매·신청·문의 경로 | 정품 여부와 해당 제품에 대한 적용 근거를 각각 확인 |
| 타사 대체 부품 | 적용 모델을 명시한 판매 상품과 그 근거 | 판매처 주장은 판매처 명시로 표시, 제조사 확인으로 승격하지 않음 |
| 범용 부품 | 후보와 규격·재질·사용 조건 확인 안내 | 미확인 조건을 명시하고 외형 유사만으로 호환 확정하지 않음 |
| 추가 해결 방법 | 동일 모델 중고 부품, 수리점·제조사 문의 | 중고 상태·확인 범위를 표시하고 수리 가능성을 임의로 보증하지 않음 |

경로에 해당하는 자료가 없으면 확인하지 못했다고 표시한다. 검색에서 찾지 못한 것을 제조사 미판매·단종으로 바꾸지 않는다.

## 데이터 설계 보완

사용자 제안의 정품·타사·범용·중고 구분을 화면에서 지원하되, 저장할 때는 출처와 상태를 분리한다. 중고 정품, 중고 타사 부품을 모두 표현하기 위해서다.

| 대상 | 필요한 정보 |
|---|---|
| 제품 변형 | 모델·별칭·용량·세대·지역·제품/설명서 출처 |
| 부품 | 정품/타사/범용/미확인, 카테고리, 부품 식별자, 규격·재질·사용 조건 |
| 판매 항목 | 부품 ID, 새상품/중고/미확인, 판매처, 판매 상태, 상품/신청 링크, 확인 날짜 |
| 적용 근거 | 제품 변형 ID, 부품 ID, 적용/제외/미확인 주장, 조건, 근거 URL·관련 내용·확인 날짜, 제조사/판매처/장착 사례 등 근거 제공 주체 |
| 검토 결과 | 확인된 조건, 미확인 조건, 불일치, 상충하는 근거, 표시 문구, 다음 확인 행동 |
| 해결 경로 | 제품 확인/부품 구매/부품 신청/수리/문의/검색, URL, 페이지 종류, 확인 상태·일시 |

호환 관계는 제품 변형과 부품 사이에 두고, 재고·품절은 개별 판매처의 판매 항목에 둔다. 한 판매처의 품절을 모든 판매처의 품절로 표시하지 않는다. 단종 주장은 별도 근거가 있어야 하며, 단종됐어도 남은 재고가 있을 수 있다.

링크는 `product`, `manual`, `purchase`, `application`, `search_results`, `repair`, `contact` 등 목적을 구분한다. 링크 확인에는 접근 성공뿐 아니라 실제 대상 상품·모델·판매 옵션이 맞는지 확인한 범위를 저장한다. 검색 결과 링크를 특정 상품 링크처럼 표시하지 않는다.

## 근거와 표시 규칙

- 제조사 확인, 판매처 명시, 장착 사례를 각각 표시한다. 정품이라는 이유만으로 사용자의 모델에 맞다고 확정하지 않는다.
- 판매처가 적용 모델을 명시했더라도 용량·세대·판매 옵션 등이 불명확하면 추가 확인을 요청한다.
- 근거가 상충하거나 적용 제외 근거가 있으면 호환 확정을 보류하거나 불일치로 처리한다. 긍정 후기 수로 상충 근거를 덮지 않는다.
- 범용 후보는 확인할 항목과 확인 방법을 제시한다. 패킹은 내경·외경·두께·단면·재질·사용 조건을, 가구 손잡이는 나사 구멍 간격·나사 규격·길이 등 해당 카테고리에 필요한 항목을 정의한다.
- 장착 사례에는 실제 제품 변형, 사용 부품, 장착 조건, 확인한 결과와 날짜를 기록한다. 한 사례를 다른 세대·용량에 일반화하지 않는다.
- 제품 모델 미확인 상태에서도 부품 종류·문의·검색 경로를 안내할 수 있지만 특정 제품용 호환 결과로 표시하지 않는다.

## 현재 구현 상태

- 관찰 전용 프롬프트와 API 계약은 유지했다. AI 출력에서 판매 URL이나 호환 결론을 사용하지 않는다.
- `shared/domain.ts`와 `data/catalog.json`에 제품·부품·판매·근거 데이터를 추가했다. 확장된 자료는 405개 제품/계열·111개 부품·487개 적용/제외 근거다. 분야·부품별 제조사 및 판매처의 적용 목록과 실제 상품 경로를 연결했다.
- 사진 업로드 → 제공 AI API 관찰 → 사용자 제품 확인 → 근거별 정품·타사 경로를 연결했다.
- 범용품 규격 확인, 국내 판매처·중고·수리 검색 링크, 공식 제조사 문의와 초안을 추가했다. 검색 결과 링크는 실제 검증 상품과 구분한다.
- 저장된 개인 장착 결과는 미검증으로 유지하며 공개 근거로 자동 승격하지 않는다.
- 모델 미확인·상품 미등록·공급자 오류도 모델명 찾기와 검색·문의로 이어진다.
- 기록 소유권, 사진 정규화, 호출 한도, 재시작 처리, 최근 찾기와 삭제·내보내기를 구현했다.
- 실시간 웹 전체 수집, 국내 실제 배송 확인, 실물 장착 검증은 수행하지 않았다. 초기 카탈로그의 상품 없는 카테고리는 안내 경로만 제공한다.

실행·검증 결과는 [README](../README.md), 시연은 [시연 안내](demo.md), 운영 설정과 환경상 미검증 항목은 [배포 안내](deployment.md)에 정리했다. 외부 배포는 실행하지 않았다.
