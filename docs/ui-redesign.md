# UI/UX 개선 기록

기존 React·Vite·Lucide와 네이티브 dialog를 유지하고, API·데이터 계약·세션·기록 처리에는 별도 재작성을 하지 않았다. 작업 중 공유 작업 공간에서 추가된 제품군·구매 필터 코드는 보존했다.

## 기존 화면의 문제

- 큰 소개 영역과 장식용 물병 일러스트 아래에 핵심 입력이 배치되어 실제 찾기까지의 거리가 길었다.
- 안내, 입력, 카탈로그, 결과에 비슷한 시각적 비중을 주어 다음 행동을 발견하기 어려웠다.
- 제품을 선택한 뒤에도 입력 영역과 소개가 길게 남고, 화면 스크롤 위치가 결과 중간에 남을 수 있었다.
- 글자 크기·간격·색상·라운드가 반복 하드코딩되어 화면 간 규칙을 관리하기 어려웠다.

## 2차 비판 검토에서 고친 것

1차 개선 뒤에도 템플릿처럼 보이는 흔적이 남아 있어 다시 걷어냈다.

- 결과 화면에서 실제 답(부품·구매 링크)이 상단 장식 약 670px 아래에 있었다. 검색 맥락 바, 탭처럼 보이지만 눌리지 않는 진행 표시, 제목, 초록 패널이 같은 제품명을 네 번 반복했다. 하나의 제품 헤더로 합쳐 첫 부품 행이 약 350px에서 시작한다.
- 슬로건 네 개(헤더·히어로·하단 배너·푸터)와 `01/02/03` 번호 모티프 다섯 곳을 제거했다. 제목은 서비스가 하는 일을 그대로 말한다.
- 통계 3열(등록 제품·부품·분야)과 큰 숫자 결과 요약은 한 문장과 판정 요약 한 줄로 바꿨다. 결과 대부분이 부품 1~3개라 36px 숫자로 강조할 값이 아니었다.
- 2열 부품 카드는 결과가 1개일 때 반쪽이 비고, 높이가 달라 들쭉날쭉했다. 행 기반 적합표로 바꿨다.
- 장식 아이콘(탭, 업로드, 방패, 반짝이, 패키지, 시계 등)을 제거했다. 남긴 아이콘은 촬영, 외부 링크, 닫기, 저장·삭제, 진행 표시뿐이다.
- 왼쪽 색 띠 패널(확인한 제품, 적용 제외)과 옅은 초록 구매 버튼을 없앴다. 채운 초록은 화면마다 한 가지 행동에만 쓴다.
- 기본값이 비활성인 주 버튼 앞에 선택 입력 두 개가 먼저 나와 첫 행동이 불분명했다. 사진·모델명 입력을 먼저, 범위 좁히기를 그다음에 둔다.

## 3차: 로고에 맞춘 시각 언어

2차 결과는 구조는 정리됐지만 겉모습이 자동 생성물처럼 보였다. 처음에는 "베이지 바탕 + 세이지 그린 + 시스템 글꼴 + 얇은 회색 선", 한 번 고친 뒤에는 "흰 바탕 + 얇은 회색 테두리 상자 + 검은 버튼 + 6px 모서리"였다. 둘 다 도구가 기본으로 내놓는 조합이다. 로고(차콜·초록, 틈으로 나뉜 둥근 면, 퍼즐 홈이 있는 상자, `딱품` 레터링)를 기준으로 시각 언어를 다시 잡았다. 서비스명은 `딱품`으로 통일했다.

- **면과 틈.** 구획은 얇은 테두리 상자가 아니라 채운 면과 여백으로 나눈다. 입력 칸·칩·탭은 테두리 없는 채운 면이다. 선은 표를 읽는 데 필요한 곳(표의 시작 2px, 행 사이 1px)에만 남긴다.
- **차콜 띠.** 화면마다 "지금 무엇을 다루는가"를 화면 폭 전체의 차콜 띠에 올린다. 첫 화면은 제안(제목)이고 입력 도구가 띠에 걸쳐 꽂힌다. 결과 화면은 확인한 제품명과 부품 종류다. 내용은 흰 바탕에 둔다.
- **초록은 브랜드의 '딱'.** 주 행동(사진 선택·부품 찾기·이 제품 선택·`명시됨` 부품의 구매 링크)과 `명시됨` 판정, 후보 일치에 쓴다. 한 화면에서 채운 초록 버튼은 한 가지 행동뿐이고, 아직 누를 수 없는 주 버튼은 회색이 아니라 옅은 초록이다.
- **판정은 색 블록.** 큰 낱말(`명시됨`·`조건 확인`·`미확인`·`근거 충돌`·`제외`)과 모양(●◐○⊘), 원래 문구를 함께 적는다. 발표장 뒤에서도 읽히고 색 없이도 구분된다. 낱말은 출처의 표현 범위를 넘지 않게 골랐다(`적합`·`맞음`이라고 쓰지 않는다).
- **서체.** IBM Plex Sans KR과 IBM Plex Mono를 직접 호스팅한다(CSP가 외부 글꼴을 막는다). 제품명·부품명·검색어·모델 코드는 모노로 찍는다. O/0, I/1을 구분해야 하는 자료이고 부품 카탈로그의 인상을 준다. 한글이 섞인 이름은 낱말 간격을 좁혔다.
- **문구.** 제목은 기능 설명이 아니라 사용자의 상황을 말한다: "뚜껑 하나 때문에 버리지 마세요". 설명은 카탈로그에 실제로 있는 부품(텀블러 패킹, 청소기 필터, 자전거 브레이크 패드)을 든다. 판정 어휘는 문장으로 설명하지 않고 결과 예시가 보여 준다.
- **모서리·크기.** 버튼·칸 10px, 입력 도구·대화상자 16px. 제목 56px, 제품명 36px, 부품명 22px, 본문 15px, 보조 12~13px.
- **로고.** 받은 이미지를 벡터로 다시 그렸다(`client/Logo.tsx`, `public/favicon.svg`). 원본 벡터 파일이 생기면 교체한다. 로고의 문구 "딱 맞는 부품, 더 오래 쓰는 일상"은 푸터에만 둔다.

## 콘셉트와 화면 구조

**부품 카운터의 적합표.** 부품마다 판정 → 부품 → 근거 → 구매 경로를 한 줄로 읽는다.

1. 첫 화면은 차콜 띠에 제목과 설명, 그 띠에 걸친 입력 도구(왼쪽), 오른쪽에 등록 자료 한 줄과 "이런 결과를 받아요" 예시를 둔다. 예시는 실제 카탈로그 항목이고 눌러서 실제 결과로 열 수 있다.
2. 입력 순서는 찾는 방법 → 사진 또는 모델명 → 범위 좁히기(선택) → 찾기다. 촬영 안내는 조용한 보조 경로로 둔다.
3. 제품 선택 단계는 후보를 먼저 보여 준다. 후보가 있으면 후보 행에만 채운 버튼을 쓰고, 검색·필터는 접어 둔다.
4. 결과 화면의 띠에는 확인한 제품명과 부품 종류가 있다. 그 아래 판정 요약 한 줄과 적합표가 이어진다. 적용 제외 부품은 접지 않고 표 아래에 둔다. 사지 말아야 할 부품을 보여 주는 것이 이 서비스의 차이다.
5. "맞는 부품이 없을 때" 영역은 선을 더 긋는 대신 바탕을 옅은 회색 띠로 바꿔 보조 영역임을 알린다.
6. 정품·조건부 적용·적용 제외·판매 상태는 원래 의미와 출처를 유지한다. 실시간 재고나 실물 장착 검증으로 확대 해석하지 않는다. 재고·검증 범위 안내는 행마다 반복하지 않고 표 아래에 한 번 적는다.

## 공통 규칙

- 색: 잉크 `#2b3135`, 보조 `#454c51`, 흐린 글자 `#60686d`, 띠 위 보조 글자 `#c6cdd0`, 바탕 `#fff`, 채운 면 `#eef1f0`, 보조 바탕 `#f2f4f3`, 브랜드 초록 `#166b3a`·`#299256`, 조건 확인 `#f2b32b`.
- 선택 상태는 차콜 채움, 주 행동은 초록 채움, 보조 행동은 2px 차콜 외곽선이다.
- 간격은 묶음 안 4~8px, 묶음 사이 16~24px, 구역 사이 48~64px로 차이를 둔다. `--space-*` 변수로 관리한다.
- 그림자는 대화상자와 알림에만 쓴다.
- 인터랙션: 140ms 색 전환, 초록 포커스 링, disabled·loading·empty·error·success 상태. 모션 감소 환경을 존중한다.
- 스타일은 `client/styles.css` 한 곳에서 관리한다. `client/photo-purchase.css`에는 줄바꿈 안전장치만 둔다.

## 반응형

- 960px 초과: 띠 안에서 제목과 설명을 7:5로, 그 아래 입력 도구와 결과 예시를 7:5로 둔다. 입력 도구는 띠에 140px 걸친다. 적합표는 4열(판정·부품·적용 근거·구매 경로)과 열 머리글.
- 960px 이하: 한 열. 적합표는 판정 블록 옆에 부품·근거·구매를 쌓고, 열 머리글 대신 칸마다 작은 이름표를 쓴다.
- 640px 이하는 데스크톱 축소판이 아니라 다른 화면이다.
  - 입력 도구는 테두리 없이 화면 폭 전체로, 띠 위로 올라오는 둥근 시트가 된다.
  - 터치 기기에서는 '카메라로 촬영'이 첫 행동(초록)이고 끌어 놓기 안내는 숨긴다. 사진이 생기면 촬영 버튼은 외곽선으로 물러나고 찾기 버튼이 화면 아래에 붙는다.
  - 판정은 부품마다 위쪽 띠로 놓인다. 부품 종류는 줄바꿈 대신 가로로 넘긴다. 제품 선택의 필터는 접어 두어 첫 화면에 후보와 선택 버튼이 보인다.
  - 대화상자는 아래에서 올라오는 시트다. 입력 글자는 16px(iOS 확대 방지), 터치 영역은 44px 이상이다.
- 긴 제품명·모델 코드·판매처 이름은 줄바꿈하고, 제품 설명은 목록에서 두 줄로 자른다. 구매 경로·근거가 없는 부품도 빈 칸 대신 안내 문장을 보여 준다.

## 후속 개선

- 대표 제품군별 실물 사진을 확보하면 결과에서 모델·외형 대조를 더 쉽게 제공할 수 있다.
- 실제 휴대폰의 카메라 권한·촬영과 Safari·Android에서 추가 기기 검증이 필요하다.
- 카탈로그·API의 별도 확장 작업이 완료되면 각 제품군의 대표 시나리오를 다시 통합 검증하는 것이 좋다.
